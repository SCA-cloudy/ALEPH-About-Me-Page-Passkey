# ALEPH 개인과제 8 제출 문서 — 내 소개 페이지에 패스키 달기

- 결과 주소(누구나 열림): https://aleph-about-me-page-passkey.vercel.app/
- 소스 주소: https://github.com/SCA-cloudy/ALEPH-About-Me-Page-Passkey
- 이 문서에 쓰인 비공개 자리의 내용·계정은 모두 **과제용으로 만들어 넣은 것**이며, 실제 개인정보는 없습니다.
- 비공개 자리는 패스키로 로그인해야만 열리므로, 열린 모습과 시험 결과는 이 문서와 `evidence/` 캡처로 남겼습니다.

## 4줄 확인 방법

1. **어디로 가나요**: 시크릿 창에서 https://aleph-about-me-page-passkey.vercel.app/ 를 엽니다(로그인 없이).
2. **무엇을 하나요(3단계 이내)**: ① 첫 화면을 봅니다. ② 맨 아래로 내려가 “나만의 자리”를 봅니다(또는 위 메뉴의 PRIVATE). ③ 같은 주소 뒤에 `/api/private/items` 를 붙여 엽니다.
3. **무엇이 보이면 통과**: ① 공개 소개 페이지(과제 1번 내용) ② “패스키로만 열립니다”와 함께 비공개 내용 없이 “서버 응답 401 · 로그인하지 않은 상태” ③ `{"error":"unauthorized","message":"패스키로 로그인해야 볼 수 있습니다."}` (401)
4. **안 될 때**: 새로고침(Ctrl+Shift+R) 후 다시 확인합니다. 비공개 내용(ARCHIVE·ROADMAP·REVIEW의 문장)이 로그인 없이 보이면 불통과입니다. 확인하는 분의 기기에는 이 사이트의 패스키가 없어 로그인할 수 없고, 이미 주인이 있는 계정이라 새로 등록하려 해도 403으로 막히는 것이 정상입니다.

## 3줄 AI와 나

1. **AI에게 맡긴 일**: 등록·로그인·세션·삭제 코드와 서버의 서명 확인 로직 작성, 가상 인증기로 하는 자동 시험, 시험 기록과 증거 문서 정리.
2. **내가 직접 판단한 일**: 비공개 항목(ARCHIVE·ROADMAP·REVIEW)과 두 계정의 내용 정하기(A=보안·네트워크, B=커피), 메모장 기능을 넣지 않기로 한 것, 새 저장소·새 DB 프로젝트 결정, 실제 기기에서 등록·로그인·삭제·다른 계정 시험을 직접 실행해 결과 확인.
3. **AI 말을 안 들은 일**: 두 번째 패스키를 만들려고 AI가 제안한 Windows Hello PIN 설정을 하지 않았습니다(내 PC가 아니라서). 대신 PC 설정을 바꾸지 않는 방법(패스키마다 사용자 식별값을 다르게 하기)으로 해결했습니다.

## 인증 설명

### ① 무엇으로 붙였나

**패스키(WebAuthn)** 입니다. 브라우저의 `navigator.credentials.create()/get()`으로 기기가 열쇠 한 쌍을 만들고, 서버는 **공개키만** 저장해 로그인 때 서명을 확인합니다. 외부 라이브러리 없이 **Node.js 내장 `crypto`로 직접 구현**했습니다(`api/_lib/webauthn.js`, `cbor.js`; 작업 환경에서 npm 레지스트리에 접속할 수 없었기 때문). 서버는 Vercel 서버 함수, 저장은 Supabase(Postgres)입니다. 비밀번호 입력칸은 어디에도 없습니다.

### ② 왜 이걸 골랐나

- 서버에 **비밀이 남지 않습니다.** 저장되는 것은 공개키뿐이라 DB가 유출돼도 그것으로 로그인할 수 없습니다.
- 서명 안에 **사이트 주소**가 들어가 가짜 사이트에서는 쓸 수 없습니다.
- 과제가 요구한 “비밀번호 없이 나만 들어가기”를 그대로 만족합니다.

### ③ 어디를 어떻게 고쳤나 (4가지 흐름)

| 흐름 | 고친 곳 | 하는 일 |
|---|---|---|
| 등록 | `api/passkey/register-options.js`, `register-verify.js`, `index.html`(등록 칸) | 서버가 일회용 질문을 만들어 보관 → 기기가 답함 → 서버가 질문·주소를 확인하고 **공개키만** 저장(이름 붙임). 취소하면 아무것도 저장하지 않음 |
| 로그인 | `login-options.js`, `login-verify.js`, `api/_lib/session.js`, `index.html`(로그인 버튼) | 요청마다 새 질문 → 서명 확인(저장된 공개키) → 질문은 그 순간 ‘사용됨’ → 세션 토큰(쿠키, 서버엔 해시만) |
| 접근 보호 | `api/private/items.js`, `session.js` | 쿠키의 세션으로 계정을 정하고 그 계정의 자료만 줌. 로그인 안 하면 401. 비공개 내용은 페이지 소스가 아니라 서버 파일(`api/_lib/private-data.js`)에만 있음 |
| 관리·로그아웃 | `logout.js`, `list.js`, `delete.js` | 로그아웃은 서버의 세션 기록 삭제, 패스키 목록(이름·날짜), 삭제(내 계정 것만, 마지막 하나는 거절) |

### ④ 확인 네 가지 — 성공과 거절 나란히

| 확인 | 성공 | 거절 | 증거 |
|---|---|---|---|
| 비공개 자료 | 로그인 후 자기 계정 자료 3개 보임(200) | 로그인 전·로그아웃 후 401, 페이지 소스에 문장 0건 | card1, card3, card5 |
| 로그인 서명 | 올바른 서명 → 200, 세션 시작 | 일부러 망가뜨린 서명 → 401 “서명이 맞지 않습니다”, 서버가 낸 적 없는 질문 → 401 | card3/console-result.json |
| 질문 재사용 | 처음 보낸 로그인 값 → 200 | 같은 값을 다시 보내면 401 “이미 썼거나…” | card3/console-result.json |
| 다른 계정 | 내 계정 자료·패스키만 보임·삭제됨 | 주소·본문에 상대 계정을 적어도 내 것만 옴, 상대 패스키 삭제 → 404, DB 개수 그대로 | card5 (B→A, A→B 양쪽) |

덧붙임: 삭제한 패스키로 로그인 → 401(card4), 계정의 마지막 패스키 삭제 → 409(card4), 이미 주인 있는 계정에 로그인 없이 패스키 등록 → 403(card2).

거절이 일어나는 소스 위치:
- 로그인 안 함 → `api/private/items.js:11`
- 계정을 정하는 곳(세션만 봄) → `api/_lib/session.js:30`
- 서명 확인 → `api/_lib/webauthn.js:139`, 질문 재사용 → `api/passkey/login-verify.js:30`
- 남의 패스키 삭제 거절 → `api/passkey/delete.js:24`, 마지막 하나 → `delete.js:25`

### ⑤ AI와 나

**AI**: 등록·로그인·세션·삭제 코드와 서명 확인 로직, 자동 시험, 기록 문서를 작성했습니다. **나**: 무엇을 비공개로 둘지·두 계정에 무엇을 넣을지 정하고, 실제 기기(Google 비밀번호 관리자)에서 등록·로그인·삭제·다른 계정 시험을 직접 실행했으며, 화면·DB 결과를 눈으로 확인해 AI가 말한 것과 맞는지 판단했습니다. 시험 중 서버 오류(500)와 같은 기기에서 패스키가 덮어쓰이는 문제는 직접 해 보고 나서야 드러났고, 그에 맞춰 고쳤습니다(docs/TESTLOG.md).

### ⑥ 아직 못 막은 것

1. **로그인 시도 횟수 제한이 없습니다.** 질문 요청과 로그인 시도를 무제한으로 보낼 수 있습니다.
2. **삭제한 패스키로 이미 시작한 세션은 로그아웃하거나 8시간이 지날 때까지 유효합니다.** 패스키를 지워도 그 계정의 열린 세션을 바로 끊지 않습니다.
3. **주인 없는 계정은 먼저 등록하는 사람이 차지합니다.** 처음 패스키를 만들 때는 로그인이 필요 없습니다(지금은 두 계정 모두 등록 완료라 막혀 있음).
4. **직접 구현한 확인 코드입니다.** 검증된 라이브러리가 아니고 기기 종류를 증명하는 정보(attestation)는 확인하지 않습니다. 서명 횟수를 늘리지 않는 동기화 패스키는 복제 감지가 되지 않습니다.
5. **‘마지막 패스키 삭제 금지’는 두 삭제 요청이 정확히 동시에 오면 경쟁할 수 있습니다.**(개수를 확인한 뒤 지우는 두 단계라서)
6. **비공개 내용이 공개 소스 저장소에 들어 있습니다.** 과제용으로 만든 내용이라 괜찮지만, 진짜 비밀이라면 이런 식으로 두면 안 됩니다.
